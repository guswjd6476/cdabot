# cdabot

텔레그램 봇 (counseling-bot과 같은 구조: TypeScript + Telegraf + Neon PostgreSQL + dayjs)

## 시작하기

```bash
npm install
cp .env.example .env   # 값 채우기
npm run dev            # 로컬 실행 (WEBHOOK_URL 비우면 폴링 모드)
```

> ⚠️ 로컬 폴링은 운영 중인 토큰으로 실행하지 마세요 (운영 웹훅이 해제됩니다). 테스트용 봇 토큰을 따로 쓰는 것을 권장합니다.

## 배포

```bash
git pull && npm install && npm run build && npm start   # dist/bot.js 실행
```

### alwaysdata (counseling-bot과 같은 방식)

1. **BotFather**: `/setprivacy` → 봇 → `Disable` (끄지 않으면 단체방의 한글 명령·일반 메시지가 봇에 오지 않음). 이미 들어간 방은 봇을 내보냈다 다시 초대
2. **SSH**: `git clone … ~/cdabot && cd ~/cdabot && npm ci && npm run build` (typescript가 devDependency라 `--omit=dev` 금지)
3. **`.env`**: `TELEGRAM_BOT_TOKEN`, `NEON_DATABASE_URL`, `ADMIN_IDS`, `CRON_SECRET`, `WEBHOOK_URL=https://<사이트 주소>/webhook`. `PORT`는 넣지 않음 (alwaysdata가 주는 값 사용)
4. **관리 패널 → Web → Sites → 추가**: 종류 Node.js, 명령 `node dist/bot.js`, 작업 디렉터리 `~/cdabot`, 주소는 서브도메인 (경로 하위 `/cdabot` 말고) — counseling-bot 사이트 설정을 그대로 복사
5. 로그에서 `001_sida_core.sql 적용`, `Webhook 등록 완료` 확인 → `https://api.telegram.org/bot<토큰>/getWebhookInfo` 에 오류 없는지 확인
6. **Scheduled tasks**: 매일 밤 `https://<사이트 주소>/cron-10pm?key=<CRON_SECRET>` 호출 (개인정보 보관기간 삭제)
7. 업데이트: `git pull && npm ci && npm run build` 후 패널에서 사이트 재시작

- `.env`에 `WEBHOOK_URL=https://도메인/webhook` 설정 → 시작 시 웹훅 자동 등록
- 크론: `/cron-10am`, `/cron-10pm` (`CRON_SECRET` 설정 시 `?key=값` 필요)

## 구조

- `src/bot.ts` — 명령어 핸들러, HTTP 서버(웹훅·크론)
- `src/db.ts` — DB 연결, `cdabot_chats` 테이블 자동 생성, 조회·수정 함수, `members` 조회
- `src/utils.ts` — 날짜/시간 파싱, HTML 이스케이프, 긴 메시지 분할 전송
- `src/core/` — 시다봇 공통 엔진: 역할(모듈) 등록, 사용자·조직·권한, 입력 세션(DB 저장), 감사 로그
- `src/sida/` — 특전대 모듈: `time.ts`(시간 계산·시간표) · `result.ts`(결과 양식·CSV) · `store.ts`(DB) · `bot.ts`(메뉴·흐름·보고서)
- `migrations/*.sql` — 시작 시 자동 적용 (적용 기록 `cdabot_migrations`). 기존 테이블은 건드리지 않음

## 기본 명령어

- `/도움말`, `/내아이디`, `/상태확인`, `/일정 10.8(목) 오후 7시`
- `관리자 점검` (ADMIN_IDS에 등록된 사용자만)

## 역할별 결과 취합 (특전대, 온라인 전도 등)

역할 이름은 자유 입력이라 새 역할을 만들 때 코드를 고칠 필요가 없습니다.

1. 관리자가 각 방에서 `/역할 특전대` (또는 `/역할 온라인전도`) → 방에 역할 지정. `/역할 해제`로 해제
2. 그 방에 `항목: 숫자` 줄이 들어간 글을 올리면 자동 접수. 항목명은 역할마다 자유롭게 정하면 됩니다
   ```
   [특전대 결과]
   전도: 3명
   섭외: 1명
   ```
   글을 수정하면 수정한 내용으로 반영되고, 날짜는 처음 보낸 날 기준입니다
3. 관리자가 `/결과 특전대` (오늘) 또는 `/결과 특전대 10.8` → 합계, 방별 합계, 미보고 방 목록

## 🪖 시다봇 — 특전대 (단체방에서 운영)

한글 명령어는 텔레그램 메뉴(setMyCommands)에 등록할 수 없어 메시지 핸들러 + 인라인 버튼으로 처리합니다. 영문 별칭: `/sd`, `/home`.

- 모든 기능을 단체방에서 사용. 봇 답장은 요청한 메시지에 답장으로 달림
- 버튼은 연 사람만 누를 수 있음 (가입 승인 버튼만 예외 — 관리자 권한은 서버에서 확인)
- 진행 중인 입력(시간·결과)은 시작한 방에서 그 사람의 메시지만 받고, 단체방에서는 30분 지나면 자동으로 무시
- 단체방 화면에서는 이름 마스킹·연락처 비공개. **개인정보 상세 결과·CSV는 요청한 관리자의 1:1 대화로 전송** (봇과 1:1 대화를 한 번 시작해 둬야 함)
- ⚠️ 대원이 단체방에 결과를 입력하면 그 메시지(이름·연락처)는 방 사람들에게 보입니다

| 명령 | 기능 | 권한 |
|---|---|---|
| `/홈`, `/역할` | 역할 선택 / 접근 가능한 역할 (`/역할 이름`은 기존 방 역할 지정 그대로) | 누구나 |
| `/특전대` | 메뉴 (미등록자는 가입 요청 버튼) | 누구나 |
| `/특전대 제출` · `내현황` · `결과` · `내결과` · `도움말` | 활동 가능 시간 제출·수정, 내 현황, 당일 결과 입력, 내 결과 수정·삭제 | 대원 |
| `/특전대 시간표 [날짜] [요일]` · `오늘현황 [날짜]` · `개인현황 [이름]` | 시간표(+CSV), 일일 통합 보고서, 개인별 주간 보고서 | 팀 관리자 |
| `/특전대 결과검색 기간:10.1~10.24 인도지역:서울` | 검색·집계·페이지·CSV | 팀 관리자 (이름·연락처는 개인정보 권한) |
| `/특전대 미제출` · `부족시간` · `마감` · `재개방 [날짜]` · `주차시작 [날짜]` · `수정허용 ID` | 주차 운영 | 팀 관리자 |
| `/특전대 대원` · `승인` · `등록 ID 이름` · `활성/비활성 ID` · `이름 ID 새이름` · `옵션` · `결과수정 번호` | 대원·선택 목록 관리 | 팀 관리자 |
| `/특전대 권한 ID member,manager,pii` · `기준 6` · `보관기간 365` · `/조직 [생성 이름]` | 권한·기준시간·개인정보 보관기간·조직 | 시스템 관리자(ADMIN_IDS) |

- **활동 가능 시간**: 월~금, 구간 개수·시각 자유 (`09:00~12:00, 14:00~17:00`, `9-12`, 시각 버튼). 겹치는 시간은 한 번만 계산, 하루 6시간(설정 가능) 이상 충족. 자정을 넘는 구간은 미지원 → `22:00~24:00`까지만 입력
- **당일 결과**: 단계별 질문 또는 `발: … / 이름: … / …` 양식 붙여넣기 → 자동 정리 → 빠진·잘못된 항목만 다시 질문 → 확인 후 저장. 같은 메시지·같은 확인 버튼은 한 번만 저장
- **개인정보**: 이름·연락처는 `pii` 권한자만 열람·CSV. 그 외 관리자는 이름 마스킹·연락처 비공개. 열람·내보내기는 감사 로그 기록. `보관기간` 설정 시 `/cron-10pm` 호출 때 지난 결과의 이름·연락처 삭제
- 첫 시작 순서: 봇 실행 → 관리자 `/특전대 주차시작` → 대원들 `/특전대` 가입 요청 → 관리자 승인 → 제출
