# 시다봇 (cdabot)

텔레그램 단체방에서 **특전대** 운영을 돕는 봇. 대원이 활동 가능 시간과 당일 결과를 제출하면, 시간표·개인별 집계·일일 보고서를 자동으로 만든다.
TypeScript + Telegraf + Neon PostgreSQL + dayjs. 다른 역할(전도교관, 전도부장)은 같은 구조로 모듈만 추가하면 된다 (`/전도교관`은 지금 "준비 중" 안내).

## 하는 일

| 구분 | 기능 |
|---|---|
| 대원 | 등록된 특전대 단체방에서 봇을 쓰면 자동 등록 (그 외 방은 가입 요청 → 관리자 승인). 텔레그램 ID로 식별 |
| 활동 가능 시간 | 월~일. 단체방에 `/활동시간` 밑에 `월/12-14,18-20` 처럼 한 줄에 한 요일 적어 보내면 바로 저장 (처음이면 안 적은 요일은 활동 불가, 이미 냈으면 적은 요일만 수정). 겹치는 시간은 한 번만 계산, 하루 6시간(설정 가능) 이상이면 충족. 마감 전까지 수정 |
| 시간표 | 실제 제출된 구간 경계로 나눈 요일별 시간표, 시간대별 인원·대원, 개인별 합계·충족 여부, 미제출·부족 대상. CSV |
| 당일 결과 | **발굴건**·**찾기건** 두 양식. 한 줄 양식을 단체방에 올리면 바로 저장 (문제없으면 👍 반응만, 빈 칸·형식 확인·중복이 있을 때만 답장. 또는 `/특전대 결과`로 단계별 입력). 중복 저장 방지, 수정·삭제 |
| 보고서 | 오늘 현황(대원별 당일 `발 n건 · 찾 n건`, 이번 주 누적, 요일별 건수, 활동 시간 제출·충족 인원, 관리자용은 항목별 통계 추가 — 단체방 현황판도 같은 내용), 개인별 주간 현황, 결과 검색·페이지·CSV |
| 운영 | 주차 시작·마감·재개방, 마감 후 개별 수정 허용, 선택 목록(인도지역·인도팀·인도자·도구·성별) 관리, 감사 로그 |

활동 **가능** 시간과 결과 건수는 따로 집계한다 (실제 활동 시간으로 보지 않음). 새 주차는 새 데이터라 지난 주차를 덮어쓰지 않는다.

## 인터뷰 추적 (`/인터뷰`, 특전대와 별개)

당일 인터뷰 결과지를 사람별로 쌓고, 카운셀링 봇이 쓰는 행정 DB(`students`·`members`, **읽기만**)에 등록됐는지·몇 단계인지 추적한다. 권한·방·데이터 모두 특전대와 따로다.

- 시스템 관리자가 결과지를 올릴 단체방에서 `/인터뷰 방등록` → 그 방에 지금 쓰는 결과지를 그대로 올리면 자동 저장
  - `▪️후속연결O / 보류 / X` 아래 `#이름/지역/인도자/인터뷰자/메모…` 줄을 사람별로 저장 (`#` 없이 `이름/…/…`로 써도 후속연결 제목 아래면 인식). 칸이 빠져도 됨 (`-`는 빈 칸, 사람 칸이 하나면 인터뷰자로 봄)
  - 연락처·`생년월일: 990315`는 메모에서 자동 인식. 같은 날 같은 이름을 다시 올리면 덮어씀. 잘못 올린 사람은 `/인터뷰 삭제 9.12 이름` (올린 본인·관리자)
  - 저장 답장에 **확인 필요** 표시: 인도자 없음 · 행정에서 못 찾음 · 행정에 같은 이름 여러 명 (후속 X 제외) → 고쳐서 다시 보내면 덮어씀
  - **구분**: 결과지 제목(첫 `#` 줄 위)에 '향수'가 있으면 **향수행사**, 없으면 **당터뷰**. 직접 지정은 `구분: 향수행사` 줄. 현황·미등록·단계 뒤에 `향수`/`당터뷰`를 붙이면 그 구분만 (예: `/인터뷰 단계 향수 10.1~10.24`), 안 붙이면 구분별로 나눠 보여줌
  - **밀린 결과**: 맨 위에 `날짜: 10.20` 줄을 넣어 봇에게 1:1로 보내면 그 날짜로 저장 (1:1 입력은 인터뷰 권한자만, 미래 날짜는 거부). 날짜 줄이 없으면 오늘
- 행정 연결: **이름 + 인도자**(인도자가 없으면 지역)로 `students`를 찾아 한 명일 때만 연결. 같은 이름이 여러 명이면 '확인 필요'. 저장할 때와 현황을 볼 때마다 미연결 건(최근 180일)을 다시 찾음. 행정 단계는 볼 때마다 새로 읽음
- `/인터뷰 행정 [기간]` (관리자 + 개인정보 권한, 1:1): 행정에 등록된 인터뷰 대상자를 **현재 단계별로** (높은 단계부터, 탈락은 맨 아래). 기본 전체 기간, 기간은 인터뷰 날짜 기준. `향수`/`당터뷰`로 거르기
- `/인터뷰 단계 [10.1~10.24]` (관리자 + 개인정보 권한, 1:1): 인터뷰 대상자 중 행정에서 **찾등·합등**이 된 사람과 구분별·인터뷰자별 건수. 기본 **전체 기간** — 찾·합 완료일이 있거나, 비어 있어도 현재 단계가 그 이상이면 포함. 기간을 적으면 그 기간에 완료일이 있는 사람만. 합등한 사람은 찾등 명단에 다시 넣지 않음
- 관리자 (봇과 1:1): `/인터뷰 현황 [10.1~10.24]` (인터뷰 수, 행정 등록·단계, 인터뷰자별·지역별) · `/인터뷰 미등록 [기간]` (후속 O·보류인데 행정에 없는 사람) · `/인터뷰 검색 이름`
- 권한: `/인터뷰 권한 ID manager,pii [이름]` (시스템 관리자). `manager` 현황, `pii` 미등록 명단·검색(이름·연락처). 방에서 올린 사람은 자동으로 `member`
- `/인터뷰 보관기간 365`: 기간이 지나면 이름·연락처·생년월일·메모 삭제 (건수·행정 연결은 유지)

## 어디서 쓰나

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 대원 | **특전대 단체방** | 활동 시간 제출, 결과 제출, 내 현황·내 결과 |
| 관리자 | **봇과 1:1 대화** (방등록·방해제만 단체방) | 시간표, 오늘 현황, 개인별 현황, 결과 검색·CSV, 미제출·부족시간, 마감·재개방·주차 시작, 가입 승인·대원 관리, 설정 |

- 장소가 틀리면 맞는 곳을 안내 (관리자 기능을 단체방에서 → "1:1 대화에서", 대원 기능을 1:1에서 → "단체방에서")
- 메뉴도 장소에 맞는 버튼만 보임. 권한 없는 기능은 어디서든 거부
- 단체방: 봇 답장은 요청한 메시지에 답장으로, 버튼은 연 사람만 누를 수 있음, 진행 중인 입력은 그 사람 메시지만 받고 30분 지나면 무시, 단체방 화면(내 결과·현황판·저장 답장)은 올린 그대로 보임
- `/특전대 방등록`한 단체방에서는 가입 요청 없이 자동으로 대원 등록 (대원 권한만, 관리자가 비활성화한 사람은 제외)
- 등록 안 된 방의 가입 요청 알림·승인 버튼은 관리자 1:1 대화로 감 → 관리자는 **봇과 1:1 대화를 먼저 시작**해 둘 것 (못 받았으면 1:1에서 `/특전대 승인`)
- ⚠️ 대원이 단체방에 결과를 입력하면 그 메시지(이름·연락처)는 방 사람들에게 보임

## 명령어

한글 명령어는 텔레그램 메뉴에 등록할 수 없어 메시지 + 인라인 버튼으로 처리 (영문 별칭 `/sd`, `/home`).

| 명령 | 기능 | 권한 (장소) |
|---|---|---|
| `/도움말` · `/홈` · `/역할` · `/내아이디` | 안내, 역할 선택, 접근 가능한 역할, 내 텔레그램 ID | 누구나 |
| `/특전대` | 메뉴 (미등록자는 가입 요청 버튼) | 누구나 |
| `/활동시간` (+요일별 줄) · `/특전대 내현황` · `결과` · `내결과` · `도움말` | 활동 시간 제출·수정, 내 현황, 당일 결과 입력, 내 결과 수정·삭제 | 대원 (단체방) |
| `/특전대 시간표 [날짜] [요일]` · `오늘현황 [날짜]` · `개인현황 [이름]` | 시간표(+CSV), 일일 보고서, 개인별 주간 현황 | 팀 관리자 (1:1) |
| `/특전대 결과검색 기간:10.1~10.24 인도지역:서울` | 검색·집계·CSV | 팀 관리자 (1:1, 이름·연락처는 개인정보 권한) |
| `/특전대 답장률 [10.1~10.24]` | 대원·도구·인도지역·인도팀별 `발굴 n → 답장온 m (x%)` (기본 이번 주) | 팀 관리자 (1:1) |
| `/특전대 만남 [기간]` | 답장온 발굴의 2차 만남 일정, 날짜별 (기본 오늘부터 7일). `내일`·`토요일`은 올린 날 기준, 날짜를 못 읽은 최근 2주 건은 따로 | 팀 관리자 (1:1, 이름은 개인정보 권한) |
| `/특전대 미제출` · `부족시간` · `마감` · `재개방 [날짜]` · `주차시작 [날짜]` · `수정허용 ID` | 주차 운영 | 팀 관리자 (1:1) |
| 단체방에서 `/특전대 방등록` · `방해제` | 이 방 사람을 자동 대원 등록 / 해제 | 팀 관리자 (단체방) |
| 결과 주제에서 `/특전대 결과주제` · `결과주제 해제` | 그 주제(토픽)에서만 발/찾 양식 받기 (다른 주제는 무시) / 해제 | 팀 관리자 (단체방) |
| 현황판 둘 주제(토픽)에서 `/특전대 현황판` · `현황판 해제` | 그날 현황(개인정보 없음) 메시지 하나를 제출될 때마다 자동 갱신, 날짜 바뀌면 새 메시지 | 팀 관리자 (단체방) |
| `/특전대 대원` (이름 눌러 대원/관리자/제외 — 관리자 지정은 시스템 관리자만, 대원만 집계) · `승인` · `등록 ID 이름` · `활성/비활성 ID` · `이름 ID 새이름` · `옵션` · `결과수정 번호` | 대원·선택 목록 관리 | 팀 관리자 (1:1) |
| `/특전대 권한 ID member,manager,pii` · `기준 6` · `보관기간 365` · `/조직 [생성 이름]` | 권한·기준 시간·개인정보 보관기간·조직 | 시스템 관리자 (`ADMIN_IDS`, 1:1) |

권한: `member` 대원 · `manager` 팀 관리자 · `pii` 개인정보 조회. 모든 명령·버튼에서 서버가 권한을 확인한다.

활동 시간 (단체방, `/활동시간` 밑에 한 줄에 한 요일):
```
/활동시간
월/12-14,18-20
화/15-18,19-21
수/불가
```
- 시간은 `09:00~12:00`, `9-12` 모두 됨, 여러 개는 쉼표. 자정을 넘는 구간은 지원하지 않음 → `22:00~24:00`까지만
- 처음이면 안 적은 요일은 활동 불가, 이미 냈으면 적은 요일만 수정

결과 양식 (단체방에, `/`로 구분 — `❗️발굴건` 같은 제목 줄은 같이 붙여도 됨. 여러 건은 한 줄에 한 건씩 한 메시지로):
```
❗️발굴건
발/이름/연락처/생년(20대초·중·후,30대,모름)/성별/인도지역/인도팀/인도자/도구/+2차만남일시,장소
예) 발/홍길동/010-1234-5678/20대중/남/서울/1팀/김철수/전단지/+10.28 19시,강남역

❗️찾기건(당터뷰+후속)
찾/이름/생년월일/인도지역/인도팀/인도자/목표월
예) 찾/이몽룡/990315/대전/3팀/성춘향/11월
```
- 한 건이든 여러 건이든 바로 저장. 문제없으면 답장 없이 👍 반응만 (현황은 현황판에 반영), 빈 칸·형식 확인·중복이 있을 때만 답장 (`/특전대 내결과`에서 수정)
- 연락처는 뒷자리 4자리만 적어도 됨 (전체 번호도 가능)
- 2차 만남(`+일시,장소`)은 없으면 안 적어도 됨 (빈 칸으로 세지 않고 다시 묻지도 않음)
- 2차 만남 일시가 적힌 발굴건 = **답장온 발굴**(더 좋은 결과), 안 적으면 **답장 안온 발굴** — 현황·내 결과·검색·현황판에서 `발 5건 (답장온 2 · 답장 안온 3)` 처럼 발굴 건수 안에서 나눠 표시
- 현황판에는 그날 올라온 결과가 대원별로 올린 양식 그대로 모여 보임
- 이미 등록된 사람(발굴건 이름+연락처 뒷자리, 찾기건 이름+생년월일)은 저장하지 않고 '중복 제외'로 알려줌
- 2차 만남은 `+일시,장소` 또는 `/일시/장소` 둘 다 됨. 빈 칸(`//`)이나 모자란 칸은 추측하지 않고 다시 질문
- 단체방 화면은 올린 그대로 보임. 관리자 1:1 검색·CSV에서 이름·연락처·생년월일은 개인정보 권한(pii) 있는 사람에게만

## 처음 운영 순서

1. 봇을 단체방에 초대 (BotFather `/setprivacy` → `Disable` 필수)
2. 관리자: 단체방에서 `/특전대 방등록` (단체방에서 아무 글이나 쓴 사람은 일단 대원으로 자동 등록. 주제(토픽)를 켜면 텔레그램이 방 ID를 바꾸는데, 봇이 그 알림을 받으면 등록을 자동으로 옮김 — 봇 업데이트 전에 이미 바뀐 방은 `/특전대 방등록` 한 번 더)
   → 1:1 대화 `/특전대 대원` 에서 관리자·제외할 사람만 눌러 바꿈 (텔레그램 정책상 말한 적 없는 사람은 목록에 안 나옴)
3. 관리자: 봇과 1:1 대화 시작 → `/내아이디`로 👑 확인 → `/특전대 주차시작`
4. 대원: 단체방에서 활동 시간·매일 결과 제출 → 관리자: 1:1 대화에서 시간표·오늘현황

## 구조

- `src/bot.ts` — 기본 명령, HTTP 서버(웹훅·크론)
- `src/db.ts` — DB 연결, 마이그레이션 실행
- `src/core/` — 공통 엔진: 역할(모듈) 등록, 사용자·조직·권한, 입력 세션(DB 저장), 단체방 버튼 보호, 감사 로그
- `src/sida/` — 특전대: `time.ts`(시간 계산·시간표) · `result.ts`(결과 양식·CSV) · `store.ts`(DB) · `bot.ts`(메뉴·흐름·보고서)
- `migrations/*.sql` — 시작 시 자동 적용 (기록 `cdabot_migrations`). 테이블은 모두 `cdabot_` 접두사

## 개발

```bash
npm install
cp .env.example .env   # 값 채우기 (WEBHOOK_URL 비우면 폴링 모드)
npm run dev
npm test               # 순수 로직 + 실제 봇 핸들러를 PGlite(WASM Postgres)·가짜 텔레그램 API로 실행. 운영 DB·토큰 불필요
```

> ⚠️ 로컬 폴링은 운영 토큰으로 실행하지 말 것 (운영 웹훅이 해제됨). 테스트용 봇 토큰 권장.

## 배포 (alwaysdata)

1. **BotFather**: `/setprivacy` → 봇 → `Disable`. 이미 들어간 방은 봇을 내보냈다 다시 초대
2. **SSH**: `git clone https://github.com/guswjd6476/cdabot.git ~/cdabot && cd ~/cdabot && npm ci && npm run build` (`--omit=dev` 금지 — 빌드에 typescript 필요)
3. **`~/cdabot/.env`**: `TELEGRAM_BOT_TOKEN`, `NEON_DATABASE_URL`, `ADMIN_IDS`, `CRON_SECRET`, `WEBHOOK_URL=https://계정명.alwaysdata.net/cdabot/webhook` (`PORT`는 넣지 않음)
4. **Web → Sites → Add**: Node.js, 명령 `node dist/bot.js`, 작업 디렉터리 `cdabot`, Addresses `계정명.alwaysdata.net/cdabot`
5. 확인: `https://계정명.alwaysdata.net/cdabot/` → `CDA Bot Server is running OK`, 로그에 `Webhook 등록 완료`, `getWebhookInfo`에 오류 없음
6. **Scheduled tasks** (선택): 매일 `https://계정명.alwaysdata.net/cdabot/cron-10pm?key=<CRON_SECRET>` — 개인정보 보관기간이 지난 결과의 이름·연락처 삭제
7. 업데이트: `git pull && npm ci && npm run build` → 사이트 Restart
